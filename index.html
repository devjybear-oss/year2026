PayOut Fee Management

Delivery · On Time

01 My Role / Scope

พัฒนาทั้ง Backend และ Frontend พร้อมออกแบบ UI และ Logic การคิด Fee เองตั้งแต่ต้น โดยทำงานร่วมกับทีม Senior ตลอดกระบวนการ

02 Result / Outcome

พัฒนาฟีเจอร์ PayOut Fee Management เพื่อรองรับการคำนวณค่าธรรมเนียม พร้อมออกแบบ Layout ที่แยกให้เห็นชัดเจนว่า Fee แต่ละรายการเรียกเก็บจากฝั่ง Receiver หรือ Merchant

03 Challenge

เงื่อนไขการคิด Fee มีรายละเอียดปลีกย่อยและมุมมองที่แตกต่างกันในแต่ละ Transaction จึงต้องออกแบบ Logic ให้ครอบคลุมทุกกรณี โดยไม่กระทบความถูกต้องของ Report

04 Skills Growth

โปรเจกต์นี้เป็นครั้งแรกที่ได้ออกแบบ UI เองตั้งแต่ต้น เพื่อให้รองรับเงื่อนไขและความซับซ้อนของงาน พร้อมทำให้เข้าใจ Business ของค่าธรรมเนียม PayOut ได้ลึกขึ้น

Admin Transfer

Admin Transfer

Delivery · Late

01 My Role / Scope

พัฒนาทั้ง Backend และ Frontend พร้อมร่วมจัดทำขอบเขตฟีเจอร์และออกแบบ Flow กับทีม Senior และทีมที่เกี่ยวข้อง

02 Result / Outcome

พัฒนาและจัดทำขอบเขตฟีเจอร์ Admin Transfer สำหรับ Back-office ให้ทีมการเงินสั่งโอนผ่าน PayOut ได้อย่างเป็นระบบ ครอบคลุมตั้งแต่การตั้งค่า Enable และจำนวนผู้อนุมัติระดับ Merchant, Flow อัปโหลด Excel → Validate → Check/Decline → Approve/Reject → ส่งต่อ PayOut ไปจนถึง Dashboard, Detail, Approval History และ Export

03 Challenge

Requirement เปลี่ยนแปลงบ่อย ต้องคุม Scope, Multi-approver และความเสี่ยงเรื่องโอนซ้ำ พร้อมประสานหลายทีมให้สรุป Flow ตรงกัน นอกจากนี้ระบบ PayOut ยังถูกปิดใช้งานระหว่างทาง ทำให้ทดสอบ End-to-End ต่อไม่ได้ตามแผนที่วางไว้

04 Skills Growth

ออกแบบและพัฒนา UI ให้รองรับการใช้งานจริงของทีมการเงิน พร้อมเรียนรู้การ Integration ระหว่าง Web Back-office กับ PayOut API และการจัดการ JSON Response ทั้งกรณีสำเร็จและผิดพลาด ทำให้เข้าใจ Domain ของระบบ PayOut มากขึ้น เช่น PayOut Merchant, PayOut Receiver และ Balance

ล่าช้าเนื่องจากระบบ PayOut ถูกปิดใช้งานในช่วงทดสอบ End-to-End

Operation Logs

Delivery · On Time

01 My Role / Scope

ออกแบบระบบและพัฒนา API ขึ้นใหม่ตั้งแต่ต้น ดูแลทั้งฝั่ง Frontend และ Operation Logs API โดยออกแบบร่วมกับทีม Senior

02 Result / Outcome

พัฒนาระบบบันทึกประวัติการเปลี่ยนแปลงข้อมูลของ ChillPay โดยแยก Frontend และ Operation Logs API ออกจากกัน ฝั่ง Frontend จะส่ง Log ผ่าน API หลัง Business Action สำเร็จ ส่วน Admin สามารถค้นหาและดูรายละเอียดข้อมูลก่อน–หลังแก้ไขได้

03 Challenge

ต้องวางโครงสร้างข้อมูลและ API ของโปรเจกต์ใหม่ตั้งแต่ศูนย์ ให้ครอบคลุมทั้งวิธีที่ Frontend และระบบอื่นเรียกใช้งานได้อย่างปลอดภัยและสม่ำเสมอ

04 Skills Growth

ได้ฝึกฝน System Design ทั้งการวางโครงสร้าง Audit Log ให้นำไปใช้ร่วมกันได้หลายระบบ รวมถึง Audit Logging, Validation และ Technical Documentation

Lessons Learned & What I’ll Improve

Locking Requirements Earlier

จากบทเรียนของ Admin Transfer ที่ Requirement เปลี่ยนบ่อยและต้องคุม Scope ระหว่างทาง ครึ่งปีหลังจะสรุปและยืนยัน Requirement ร่วมกับทีมที่เกี่ยวข้องให้เรียบร้อยก่อนเริ่มพัฒนา

Planning for External Test Dependencies

จากกรณีที่ทดสอบ End-to-End ต่อไม่ได้เมื่อระบบที่เชื่อมต่ออยู่ถูกปิดใช้งาน จะระบุ Dependency ของการทดสอบตั้งแต่ต้นโปรเจกต์ พร้อมเตรียมทางเลือกสำรองไว้ล่วงหน้า

Sharing Test Results More Clearly

จากผลการทดสอบอัตโนมัติที่มีอยู่จำนวนมากแต่ยังเข้าใจยากสำหรับคนนอกสาย Dev ครึ่งปีหลังจะสรุปเป็น Test Report ที่อ่านง่าย เพื่อสร้างความมั่นใจก่อน Release ให้กับทั้งทีม ไม่ใช่แค่ทีมพัฒนา
